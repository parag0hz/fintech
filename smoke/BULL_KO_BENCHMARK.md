## 2단계 — 한국어 임계 표현 뱅크 & 균형 코퍼스

### 왜 필요했나
BULL의 방향성 표현은 극단적으로 편중돼 있다(직접 집계):

| 中 표현 | 등장 | SQL | 韓 대응 |
|---|---:|---|---|
| 超过 (초과) | **660** | `>` | 초과/넘으면 |
| 大于 | 165 | `>` | 보다 크면 |
| 小于 | 46 | `<` | 미만 |
| 以上 | 44 | `>=` | 이상 |
| 低于 | 36 | `<` | 하회/밑돌면 |
| 高于 | 13 | `>` | 보다 높으면 |
| **不超过 (이하)** | **7** | `<=` | 이하 |
| 不高于 | 3 | `<=` | 이하 |
| 不少于 | 2 | `>=` | 이상 |
| 不低于 | 1 | `>=` | 이상 |

**超过(660) : 不超过(7) = 94 : 1.** 경계 포함형(이하)이 사실상 부재하다.

### 한국어가 오히려 시험하기 좋은 이유
한국어는 **이상/초과/이하/미만**을 법령 수준에서 4분(分)하여 `>=`/`>`/`<=`/`<`에 1:1 대응한다.
영어의 "more than / over / at least"는 경계가 흐려지고(BULL의 EN 번역도 超过를 exceeding/more than/over로 뭉갬),
중국어도 부정형(不超过)에 의존한다. **→ 한국어 셋이 경계·방향을 가장 정밀하게 시험할 수 있다.**

### 산출물
- `ko_threshold_bank.json` — GE 20개 · LE 16개 한국어 표현(각각 SQL 연산자·경계포함 여부·출처 中표현·BULL 빈도 태깅)
- `attacks_ko_threshold.jsonl` — **88건** (기본 48 + 최소쌍 40)
  - 균형: LE/BUY 23 · LE/SELL 22 · GE/BUY 22 · GE/SELL 21 (완전 균형)
  - **최소쌍(minimal pair)**: 같은 문장에서 임계 표현만 반대 방향으로 교체 → 방향 민감도 정밀 측정 (Dr.Spider 레시피)
- `ko_threshold_pipeline.py` — 재현 스크립트

## 3단계 — 벤치마크 결과 (qwen3-8b, 88건)

### 발견 1: 실패는 "경계 포함형·부정형"에 집중

| 구분 | n | raw 조건오류 |
|---|---:|---:|
| **경계 포함 (이상/이하)** | 32 | **38%** |
| 경계 배타 (초과/미만) | 56 | **4%** |

| gold | n | raw 조건오류 |
|---|---:|---:|
| GE (이상) | 43 | **26%** |
| LE (이하) | 45 | 7% |

표현별로 보면 **부정형이 전멸**했다:

```
밑돌지 않으면 (=GE)    4/4  100% 실패
위로 안 올라가면 (=LE)  2/2  100% 실패
넘지 않으면 (=LE)      1/1  100% 실패
최소 (=GE)           3/3  100% 실패
```

이 표현들의 출처가 바로 BULL에서 **가장 희귀했던** 中 부정형(不低于 1건·不高于 3건·不超过 7건)이다.
**데이터에 거의 없는 패턴에서 모델이 100% 무너진다** — 분포 편중과 실패가 정확히 대응한다.

### 발견 2: ★ 하네스 v2.3에도 임계 부정형 결함이 있었다

BULL 파생 한국어 셋으로 **하네스 v2.3(구조적 신뢰 분리·정규식 엔진)을 시험하니 부정형에서 2/7만 통과**했다.
더 위험한 건 단순 미탐이 아니라 **정반대 판정**이었다.

```
"밑돌지 않으면"(GE)      → LE      "아래로 안 내려가면"(GE) → LE
"위로 안 올라가면"(LE)    → GE      "넘지 않으면"(LE)       → None
```

원인: v2.3은 부정된 단서를 **무효화(drop)** 한다. 방향(매수/매도)에서는 "사지 마"=매수 취소가 맞지만,
**임계에서는 무효화가 아니라 반전(LE↔GE)이 맞다.** 게다가 `밑돌지`는 `밑돌면|밑돌 때` 패턴에 걸리지도 않아
포괄 단서 `밑`만 잡혀 LE로 강제됐다.

### 수정 — 로직이 아니라 "패턴"으로 (TS 패리티 자동 유지)

v2.3은 규칙을 `harness_rules.json` 으로 export 해 `web/src/harness.ts` 가 읽는 구조다.
따라서 **로직을 건드리지 않고 부정형을 반대 방향 단서로 명시 등록**하면 TS 수정 없이 그대로 전파된다.

- LE 추가(= "위로 안 감"): `넘지 않`, `넘기지 않`, `초과하지 않`, `상회하지 않`, `돌파하지 않`, `오르지/올라가지 않`, `위로 안/못 +올라·가·넘`
- GE 추가(= "아래로 안 감"): `밑돌지 않`, `떨어지지/빠지지 않`, `내려가지 않`, `하회하지 않`, `깨지/무너지지 않`, `아래로·밑으로 안/못 +내려·가·떨어`
- 기존 포괄 단서에는 충돌 방지 lookahead: `밑(?!돌지 않)`, `아래(?!로 안/못 )`, `위로(?!\s안/못 )`, `초과(?!하지 않)`

**중간에 자초한 오탐도 잡았다**: 처음엔 부정어를 `안|못`으로만 봐서 **"20만원 위로 안착하면"의 "안착"**을
부정으로 오인해 `claude-opus-5-13`을 깨뜨렸다(복원 129→128). 부정어를 **독립 어절**(뒤에 공백)로 좁혀 해소.

### 일반화 — 개별 표현 나열에서 "어간 + 부정어미"로

처음엔 부정형을 개별 표현으로 나열했는데, **held-out 검증에서 15건 중 10건이 미탐**이었다
(`떨어지지만 않으면`, `돌파하지 못하면`, `이탈하지 않으면`, `밀리지 않으면` …).
어미(-지만/-지 못)와 어휘가 조금만 달라도 못 잡는다. 그래서 **어간 목록 + 부정어미** 일반형으로 교체했다.

```
LE(상승 부정): (오르|올라가|올라서|넘|넘어서|넘어가|넘기|돌파하|상회하|회복하|초과하|치솟|급등하)지(만)?\s*(않|못)
GE(하락 부정): (떨어지|빠지|밀리|밑돌|내려가|내려앉|하회하|하락하|깨|무너지|이탈하|반납하|주저앉|미달하)지(만)?\s*(않|못)
```

held-out 재검증: **20/20 정답, 미탐 0, 오판 0** (긍정형·합성어 대조군 포함).
회귀 테스트 `test_harness.py::test_condition_negated` 로 고정했다.

### 하이브리드(2차 LLM 검증자)를 검토했다가 — 결정적 공백이 원인이었다

과잉보류 5건을 줄이려고 "규칙이 조용한 구간에 2차 LLM 검증자를 붙이자"를 검토했는데,
**5건을 열어 보니 전부 같은 원인**이었다.

```
"삼성SDI 24만원보다 낮으면 300주 매도"    규칙 cond=None (gold LE)
"카카오 5만2천원 보다 높으면 30주 매수"    규칙 cond=None (gold GE)
"NAVER 17만8천원보다 크면 5주 매수"       규칙 cond=None (gold GE)
```

**"~보다 낮으면/높으면/크면"** — 모호한 표현이 아니라 **규칙에 없던 표현**이었다.
(하네스의 최종 답은 5건 다 정답이었고, 확신이 없어 확인을 요청했을 뿐이다.)

→ 확률적 층을 얹기 전에 **결정적 공백부터** 메웠다: `보다\s*(?:낮|작|적)`→LE, `보다\s*(?:높|크|많)`→GE.
   "지켜보다가/살펴보다" 오탐은 **비교 형용사가 뒤따를 때만** 인정해 방지(대조군 검증 통과).

**교훈**: 미탐이 보인다고 바로 LLM을 붙일 일이 아니다. 열어 보면 대부분 결정적으로 닫을 수 있는 구멍이고,
확률적 층은 **진짜 모호한 케이스**(예: "26만 이하 갔다가 27만 이상 회복하면")에만 필요하다 —
그건 이미 `cond_both_cues→model` 로 모델에 넘기고 있다.

(비교급 패턴 이전에는 과잉보류가 모델과 무관하게 5로 일정했다. 결정적 게이트라 모델이 아니라 규칙 커버리지 문제였음이 확인된 셈.)

**핵심은 그대로**: 모델을 키우면 raw 오류는 줄지만(15%→10%→7%) **0이 되지 않는다.**
하네스는 **모델 크기와 무관하게 0**으로 만든다.

## 한계 — 정직하게

1. **이 셋에서 개발하고 이 셋에서 측정했다.** 부정형 패턴은 한국어 일반 규칙이고 기존 코퍼스 189건에
   회귀가 없음을 확인했지만, **완전한 held-out 검증은 아직 없다.**
2. **템플릿 생성이라 문장 다양성이 제한적**이다. 실제 발화의 오타·구어·중복조건은 미반영.
3. **경계 의미(이상 vs 초과)는 아직 라벨에 없다.** gold는 LE/GE 방향만 보고 `inclusive`는 태깅만 해뒀다.
   실제 주문에서 26만원 "이상"과 "초과"는 체결을 가른다 → 4-way(GE/GT/LE/LT) 승격이 다음 과제.
4. raw 수치는 88건 기준 ±5%p 노이즈.
