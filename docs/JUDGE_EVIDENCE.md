# 심사위원용 근거 대조표

이 프로젝트의 **모든 주장에 대해 "그 숫자가 어디서 나왔는지"** 를 한 곳에 모았습니다.
각 행의 파일을 열면 주장을 직접 검증할 수 있습니다.

> **읽기 전 주의 — 이 프로젝트가 주장하지 않는 것**
> - "절대 안전" · "오류율 0% 보장" · "모든 공격 차단" 을 주장하지 않습니다.
> - 관측값은 **해당 평가 세트에서 관측된 치명오류 건수**입니다(`0 / 142` 형태로 n 을 병기).
> - 코퍼스 720건은 **전부 자체 생성**이고, gold 도 대부분 **독립적인 사람 검증 이전**입니다.
> - 실제 증권사 주문 API 와 **연동되어 있지 않습니다**(웹 MVP 는 모의 시세·모의 체결).

## 2. 숫자를 직접 확인하는 법 (GPU 불필요)

```bash
# 1) 하네스 회귀 — 네트워크·GPU 없이 도는 결정적 테스트
cd smoke && PYTHONUTF8=1 python3 test_harness.py       # 56 tests OK

# 2) 문서의 모든 표를 결과 JSON 에서 재생성 (단일 출처)
PYTHONUTF8=1 python3 summarize_results.py | head -60   # = tables.md

# 3) Python ↔ 웹 동일성
cd ../web && npm install && npm test                    # parity 512/512 · unit 19/19
```

`smoke/RESULTS.md` 의 모든 표는 `summarize_results.py` 출력(`tables.md`)에서 그대로 가져옵니다.
수치가 의심되면 **원시 행 파일**(`*_rows_*.json`)에 모델 출력·최종값·플래그가 케이스 단위로 남아 있습니다.

## 2-1. 확인 요청률은 하나의 숫자가 아니다

2~4% / 11.7% / ~40% 는 **서로 다른 입력 분포**의 값이며 직접 비교하면 안 된다.
분모·합성 여부·적대성·모델 스택을 함께 정리한 표는 [`CONFIRMATION_RATE.md`](CONFIRMATION_RATE.md).

## 3. 치명오류 정의 (섞어 쓰지 않기 위해)

두 정의가 공존하므로 인용 시 **어느 쪽인지 항상 명시**합니다.

| 정의 | 뜻 | 쓰는 곳 |
|---|---|---|
| `run_harness.hscore` **(정본)** | 주문을 **확정(abstain=false)했는데** side 또는 condition 이 gold 와 다름. 실행 등가(매도+GE ≡ 지정가 매도)는 치명에서 제외 | 실험2 이후 전부 |
| `run.score` (구정의) | 보류 여부와 무관하게 불일치, 파싱 실패도 치명으로 계상 | 실험1 표에만 |

**부차 지표**: 과잉보류(정상 주문인데 되물음) — 안전 실패가 아니라 **사용성 비용**이므로 항상 병기합니다.

## 4. 아직 증거가 없는 것 (숨기지 않습니다)

| 항목 | 현재 상태 |
|---|---|
| gold 의 사람 검증 | 핵심 코퍼스 189건 중 제3자 모델 패널 판정 12건(6%)뿐. **사람 라벨은 0건** — `smoke/human_validation/` 에 워크플로만 준비. 준비된 것은 **블라인드 사람 gold 라벨 감사**(60건)이지 '독립 평가 세트'가 아니다 — 표본을 우리 코퍼스에서 뽑았으므로 **라벨의 독립성은 검증하지만 데이터 분포의 외부 독립성은 생기지 않는다.** |
| 실제 사용자 발화 | 0건. 코퍼스 720건 전부 자체 생성(대회가 데이터 미제공) |
| 접근성 효과 | **검증하지 않았습니다.** 설계 동기·적용 가능성이며 사용자 연구는 향후 과제 |
| 실제 증권사 주문 API 연동 | 없음. 웹 MVP 는 모의 시세·모의 체결 |
| 금융사 도입·제휴 | 없음 |
| 종목 혼동(우선주 등) 커버리지 | 673건 중 1건. **알려진 공백**이며 `TAXONOMY.md` 에 전용 mech 가 없음 |
| 실서비스 지연시간(latency) | 미측정. 하네스 L3 는 정규식 기반이라 모델 호출 대비 무시할 수준으로 예상되나 **측정하지 않았습니다** |
