# 확인 요청률 — 하나의 숫자가 아닌 이유

여러 문서에서 확인 요청률(과잉보류)이 2~4%, 11.7%, ~40% 등으로 다르게 나옵니다.
**이건 모순이 아니라 서로 다른 입력 분포의 값**입니다. 다만 그렇게 읽히도록 분모와
코퍼스 성격을 같이 적지 않은 것은 우리 잘못이므로, 여기에 한 표로 모읍니다.

**확인 요청 = 주문을 확정하지 않고 "이 주문 맞으신가요?"를 한 번 더 묻는 것.**
오주문이 아니라 **한 단계 추가**이며, 사용자가 확인하면 그대로 나갑니다.
안전 실패가 아니라 **사용성 비용**이므로 치명오류와 따로 셉니다.

## 코퍼스별 실측 (하네스 v2.5 · 4bit Qwen3-8B-AWQ · 로컬 vLLM)

| 코퍼스 | n | 합성? | 적대적? | 확인 요청 | 비율 |
|---|---:|---|---|---:|---:|
| 한국어 임계 (BULL 파생) | 88 | 합성(템플릿) | 아니오 | 0 | **0.0%** |
| AgentDojo 파생 인젝션 | 72 | 합성(프레이밍 이식) | **예**(인젝션) | 0 | **0.0%** |
| BFCL 파생 보류 판단 | 30 | 합성(템플릿) | 아니오 | 1 | **3.3%** |
| 프론티어 공격 (하네스 모름) | 142 | 프론티어 LLM 생성 | **예** | 9 | **6.3%** |
| 자체작성 (사람이 씀) | 47 | 사람 작성 | 일부 | 5 | **10.6%** |
| 일상어체 합성 (구 "phrasebook") | 240 | **합성**(LLM 생성 문체 13종) | 아니오 | 28 | **11.7%** |
| 적응형 (규칙 전문 공개 후) | 31~39 | 프론티어 LLM 생성 | **예**(규칙 인지) | — | **~40%** |

> **모든 코퍼스가 자체 생성입니다.** 실제 사용자 발화는 **0건**입니다(대회가 데이터 미제공).
> "일상어체 합성"은 은어·방언·오타·음성 잡음 등 **일상 말투를 흉내 낸 LLM 생성 문장**이지
> 수집된 실사용자 발화가 아닙니다. 이전 문서에서 "실사용자 말투"로 부른 것은 부정확한 표현이었습니다.

**모델 환경에 따른 차이** (같은 코퍼스 47건, 같은 스크립트):

| 모델 스택 | 확인 요청 | 비율 |
|---|---:|---:|
| 풀정밀 Qwen3-8B (클라우드) | 1 / 47 | 2.1% |
| 4bit Qwen3-8B-AWQ (온프레미스) | 5 / 47 | **10.6%** |

양자화는 치명오류를 늘리지 않았지만(양쪽 다 0) **되묻는 횟수를 약 5배로** 늘렸습니다.

## 이 숫자들을 직접 비교하면 안 되는 이유

각 행은 **입력 분포가 다릅니다.** 인젝션이 섞인 코퍼스와 정상 주문 코퍼스의 확인 요청률을
나란히 놓고 "6.3% vs 11.7%" 라고 비교하는 것은 의미가 없습니다.
분모(n)와 코퍼스 성격(합성/적대적/모델 스택)을 함께 보아야 합니다.

## 그래서 무엇을 말할 수 있나

읽어야 할 방향은 "평균이 몇 %인가"가 아니라 **개입이 언제 늘어나는가** 입니다.

- 방향·조건이 문자로 분명한 경우(한국어 임계 88건) → **0.0%**. 명확하면 되묻지 않습니다.
- 인젝션이 있어도 발화 자체가 분명하면(AgentDojo 72건) → **0.0%**. 공격은 막되 사용자는 안 귀찮게 합니다.
- 표현이 흐릿해질수록(일상어체 합성) → **11.7%**.
- **공격자가 규칙을 알고 확인 규칙을 노려 만들면** → **~40%**.

즉 **위험도가 올라갈수록 fail-closed 가 더 적극적으로 개입**합니다. 이건 버그가 아니라
"모르면 확정하지 않는다"는 설계가 의도대로 동작한다는 뜻입니다.

## 정직하게 남기는 부담

- 일상어체 합성 240건의 **11.7%는 낮지 않습니다.** 열 번에 한 번 이상 되묻는 셈입니다.
- **온프레미스 4bit 에서 더 늘어납니다**(2.1% → 10.6%). 우리가 주장하는 배포 환경이
  하필 사용성이 가장 나쁜 조건입니다.
- 실제 사용자 발화로 측정한 적이 **없습니다.** 위 수치는 전부 합성 코퍼스 기준입니다.
- 되묻기가 실사용에서 견딜 만한 수준인지는 **사용자 연구로 검증하지 않았습니다.**
